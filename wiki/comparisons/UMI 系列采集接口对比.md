# UMI 系列采集接口对比：UMI / FastUMI / ActiveUMI

> **核心命题**：三者共享同一目标——**robot-free 地采集可直接训练机器人策略的演示数据**——但在「位姿从哪来」「视觉从哪来」「动作怎么表示」三个轴上做出了截然不同的取舍。

---

## 一、演进主线

```
UMI (Chi 2024)              手持夹爪 + GoPro + ORB-SLAM3 + 相对轨迹 + Diffusion Policy
      │                     ✅ 极轻、无标定、可野外；❌ 夹爪强耦合、VIO 脆弱、只有腕视角
      │
      ├── FastUMI (2025)    换定位方案：T265 专用 VIO 模块；换机械接口：标准化插拔指尖
      │                     ✅ 硬件解耦、抗遮挡、10k 条开源数据集；❌ 仍是腕视角、仍被动
      │
      └── ActiveUMI (2025)  换整个平台：VR 头显 + 改装控制器；加动作维度：头部 6-DoF
                            ✅ 精度 2.5×、主动视角、双向反馈；❌ 需标定、需穿戴、需主动头
```

**两条改进路线的分野**：
- **FastUMI 走「工程收敛」**：保留 UMI 的全部设计哲学（腕视角、相对轨迹、无标定），只把不可靠的模块换掉，目标是**把 UMI 变成真正即插即用的工业级工具**。
- **ActiveUMI 走「范式扩展」**：为了引入主动感知，**主动放弃**了 UMI 的相对轨迹与无标定特性，目标是**把 UMI 的能力上限从「手能做什么」推到「眼+手能做什么」**。

## 二、全维度对比

| 维度 | UMI (Chi 2024) | FastUMI (Zhaxizhuoma 2025) | ActiveUMI (Zeng 2025) |
|---|---|---|---|
| **位姿来源** | ORB-SLAM3（GoPro 鱼眼 + 内置 IMU） | RealSense T265 自包含 VIO @ 200 Hz | VR inside-out（头显三角测量控制器 IR LED） |
| **定位精度** | MoCap: < 1 cm / < 4° | 10.5 mm（无遮挡）→ 23.3 mm（重度遮挡） | RPE 4.0 mm（同实验 UMI 10.1 mm） |
| **定位失效域** | 无纹理场景、长时遮挡、需预先建图 | 长时遮挡累积漂移（靠静止复位 + 回环缓解） | 控制器出头显视野、强光/户外红外干扰 |
| **视觉源** | 腕部鱼眼 ×1/臂（155°）+ 物理侧镜伪立体 | 腕部 GoPro 鱼眼（1920×1080@60fps） | 腕部鱼眼 ×2 + **HMD 头相机（可动）** |
| **视角性质** | 被动，末端执行器中心 | 被动，末端执行器中心 | **主动，策略预测头部 6-DoF** |
| **动作表示** | **相对** EE 轨迹 $\Delta T_t = T_{t_0}^{-1}T_t$ | 相对 TCP（DP）/ 绝对关节（ACT）双支持 | **绝对**坐标（统一世界系），20 DoF |
| **标定需求** | 几乎无 | 消除外部标定（T265 自包含） | **强依赖**：零点重置 + placeholder 夹具 + 触觉确认 |
| **夹爪耦合** | 强绑定 UMI 专用平行夹爪 | 标准化插拔指尖，覆盖 OXE >90% 夹爪型号 | 复制机器人**原装**夹爪挂到控制器（非侵入） |
| **夹爪宽度测量** | ArUco 标记连续追踪 | ArUco 像素距离线性映射 | 微电机直驱（直接读取指令值） |
| **操作员反馈** | 无 | 无 | VR 渲染机器人手臂 + 坐标轴 + 触觉振动 |
| **运动学约束处理** | 事后 URDF 过滤（丢数据） | PoseACT / Smooth-ACT 在算法侧缓解 | **事前**沉浸式可视化对齐 |
| **策略主干** | Diffusion Policy (DDPM U-Net) + CLIP ViT | DP / ACT / Smooth-ACT / PoseACT / Depth-DP | **π0（flow VLA）**，语言条件 |
| **机器人侧要求** | 任意臂 + UMI 同款夹爪 | 任意臂 + 插拔指尖 + 可调相机支架 | 双臂 + **第三臂作为主动头**（20 DoF） |
| **穿戴负担** | 手持一个夹爪，极轻 | 手持设备（GoPro + T265 + 指尖） | 头显 + 背包（电池 + PC） |
| **采集速度** | 接近裸手 | 接近裸手 | 裸手的 1.49–2.06×（遥操作 2.63–3.27×） |
| **成本** | $371（夹爪 $73 + GoPro $298） | 未统一披露；T265 已停产是隐患 | 未披露；Quest 3S 为消费级 |
| **开源数据集** | 论文级演示数据 | **10,000 条 / 22 任务 / 19 类物体** | 未披露规模 |

## 三、三个关键设计张力

### 张力 1：相对轨迹 vs 绝对坐标

这是整个 UMI 系列最深的分歧点。

- **UMI 的立场（有实证）**：改用绝对坐标动作会让 Cup Arrangement 从 100% 崩到 **25%**——标定误差主导。相对轨迹天然抗 SLAM 漂移、抗相机位移、无需绝对标定，是「in-the-wild」的技术根基。
- **ActiveUMI 的反转**：主动感知**强制要求**绝对坐标——头部位姿与双手位姿必须表达在同一世界系里，策略才能学到「头看向哪里 ↔ 手在哪里」的空间关系。相对轨迹无法表达跨肢体空间对齐。

> **结论**：ActiveUMI 的三重标定流程不是画蛇添足，而是**为主动感知支付的必然代价**。系统由此从 stateless 变为 stateful。

### 张力 2：视角来源——腕部 hack vs 独立头部

- **UMI 路线**：把全局上下文硬塞进腕相机。代价是两个 hack——155° 超广角（降到 69° FoV 则 100% → **55%**）+ 物理侧面镜子做伪立体（去掉则 100% → **85%**）。
- **ActiveUMI 路线**：全局上下文交给独立头相机，腕相机回归纯局部细节。腕部 hack 不再必需，是架构层面的简化。

实证：ActiveUMI 内部消融显示，即使是**固定**顶部相机也稳定优于纯腕视角（42% vs 26%），说明第三人称视角对复杂双臂任务提供互补信息；而**可动**头相机再加 28 个点。

### 张力 3：吞吐量 vs 数据维度/精度

| | UMI | FastUMI | ActiveUMI |
|---|---|---|---|
| 单位时间采集量 | 最高 | 高 | 最低（1.49–2.06× 裸手） |
| 单条轨迹信息量 | 基线 | 基线（+深度伪标签） | **最高**（+头部 6-DoF） |
| 位姿精度 | 基线 | 视遮挡而定 | **最高**（4.0 mm） |

ActiveUMI 在 UMI 最本质的卖点（吞吐）上是**净退步**，换来维度与精度。这是明确的 trade-off，**不是帕累托改进**。

不过 ActiveUMI 的混合训练实验给出了一个缓解论证：**仅混入 1% 真机遥操作数据即可把衬衫折叠从 80% 提到 95%**（注意：20 trials，统计功效不足）。若成立，则「低吞吐但高质量」的数据配上极少量真机锚定，可能比「高吞吐但低维度」更划算。

## 四、选型建议

| 场景 | 推荐 | 理由 |
|---|---|---|
| 户外 / 移动大范围 / 多地点海量采集 | **UMI** | 极轻、无标定、无穿戴；VR 红外在户外受干扰 |
| 动态高速任务（投掷、快速插入） | **UMI** | 延迟匹配 + IMU 感知追踪专为快速运动设计 |
| 需要跨多种机器人平台快速部署 | **FastUMI** | 标准化插拔指尖 + T265 免标定，工程摩擦最小 |
| 需要现成大规模数据集起步 | **FastUMI** | 10k 条 / 22 任务开源数据集 |
| 长程、抗遮挡、双臂协同（叠衣、收纳、装配） | **ActiveUMI** | 主动视角是这类任务的性能瓶颈所在 |
| 目标平台是 humanoid / 带主动头的双臂 | **ActiveUMI** | 观测-动作结构天然对齐，无 embodiment 错配 |
| 高精度装配（mm 级） | **ActiveUMI** | RPE 4.0 mm，且可主动凑近观察 |

## 五、开放问题

1. **能否兼得？** 是否存在「头部用绝对坐标、双手用相对轨迹」的混合动作表示——保留 UMI 的抗漂移特性，同时表达头-手空间关系？论文未探讨，是明显的后续方向。
2. **VR + SLAM 融合定位**：两者失效域互补（VR 怕出视野/强光，SLAM 怕无纹理/遮挡）。融合方案可能同时突破户外与桌面场景。
3. **主动感知能否从被动数据中蒸馏？** ActiveUMI 需要专门采集头部轨迹。是否可以从大规模第一人称人类视频（Ego4D）中学习注意力先验，降低采集成本？
4. **无主动头机器人的降级部署**：ActiveUMI 策略预测的头部 6-DoF 在固定相机平台上如何利用？能否作为辅助监督信号提升表征质量而不实际执行？
