## TL;DR

ARIS (Auto-Research-In-Sleep) is a **lightweight, Markdown-only autonomous ML research harness** built on top of LLM agent tools (primarily [[wiki/entities/tools/Claude Code]]). Its core innovation: **cross-model adversarial review** — the executor model (Claude) and reviewer model (GPT-5.5 via Codex MCP) are kept separate, preventing the self-play blind spots that occur when a single model reviews its own work. The system is organized as 65+ plain-Markdown `SKILL.md` files composable into 5 named Workflows covering the full research lifecycle from idea discovery to rebuttal. Zero dependencies, zero lock-in — every skill works with any LLM agent that can read a Markdown file.

## 核心问题与设计哲学

### "Plausible Unsupported Success" 问题

自主研究系统的根本风险：当 executor 与 reviewer 是同一模型（或同一家族）时，reviewer 的批评模式与 executor 的生成模式高度相关，形成 **自我博弈（self-play）**——executor 学会预判 reviewer 的期望并产生"表面合理"的结果，而不是经过真正严格检验的结果。

### 对抗式 vs 随机式框架

ARIS 用 bandit 理论做类比：
- **单模型自评**：随机 bandit（奖励噪声可预测）——容易博弈
- **跨模型评审**：对抗 bandit（reviewer 主动探寻 executor 未预期的弱点）——更难博弈

对抗 bandit 比随机 bandit 从根本上更难欺骗。两模型设计是 1→2 的最大收益点（打破自我博弈盲区），2→4 边际递减且成本翻倍。

### 设计哲学

> *"A methodology, not a platform."* — ARIS 的价值在于**研究工作流本身**，而非特定技术栈。任何能读取 Markdown 的 LLM agent 都可运行 ARIS skills。

## 三层架构

```
┌────────────────────────────────────────────┐
│  Assurance Layer（3 阶段审计级联）           │
│  experiment-audit → result-to-claim        │
│  → paper-claim-audit → citation-audit      │
├────────────────────────────────────────────┤
│  Orchestration Layer（5 Workflows）         │
│  W1 → W1.5 → W2 → W3 → W4 + Meta          │
├────────────────────────────────────────────┤
│  Execution Layer（65+ SKILL.md 文件）        │
│  纯 Markdown，无框架，任意 agent 可读        │
└────────────────────────────────────────────┘
```

### Execution Layer — Skills

每个 skill 是一个独立的 `SKILL.md` 文件，包含：
- 触发条件（何时调用）
- 分阶段执行步骤
- 与其他 skills 的组合方式
- 可配置参数（effort / reviewer / difficulty 等）

### Orchestration Layer — Workflows

5 个命名 Workflow 将 skills 链接成端到端流水线（见下节）。

### Assurance Layer — 审计级联

4 层证据-声明审计（每层由独立的 fresh-context reviewer 执行）：
1. `/experiment-audit`：实验代码完整性（虚假 ground truth、score 归一化欺骗等）
2. `/result-to-claim`：结果→声明的科学合理性
3. `/paper-claim-audit`：论文中每个数字与原始结果文件的零上下文核查
4. `/citation-audit`：每条引用的存在性、元数据正确性、引用语境适当性

## 跨模型评审机制 (Cross-Model Review)

### Executor / Reviewer 分离

| 角色 | 默认模型 | 特性 |
|---|---|---|
| Executor | Claude Opus 4.7（via Claude Code） | 快速、流畅执行；写代码和文本 |
| Reviewer | GPT-5.5 xhigh（via Codex MCP） | 慢而严谨；独立批评 |

### 评审独立性协议

- **Reviewer Independence Protocol**：每轮评审使用全新线程（fresh thread），reviewer 不接收 fix summary，防止"客气收敛"
- **Review Tracing**：完整 prompt/response 对保存到 `.aris/traces/`，可事后审计 reviewer 独立性
- **REVIEWER_BIAS_GUARD=true**：每轮均强制 fresh context

### 模型路由选项

| Executor | Reviewer | 场景 |
|---|---|---|
| Claude Code | GPT-5.5 xhigh (Codex MCP) | 默认配置 |
| Claude Code | GPT-5.5 Pro (Oracle MCP) | 最强审查（`— reviewer: oracle-pro`） |
| Codex CLI | Claude Code (claude-review MCP) | Codex 执行 + Claude 审查 |
| Codex CLI | Gemini 3 Pro (gemini-review MCP) | Codex 执行 + Gemini 审查 |
| 任意 executor | Kimi / GLM / MiniMax / DeepSeek | 纯国产模型组合，零 OpenAI/Anthropic API |

### 终止条件

- **自动**：达到预设轮数（`lite` 2轮 / `balanced` 4轮 / `max` 6轮 / `beast` 8轮）或 reviewer 给出 "clear accept" 信号
- **人工干预**：`human checkpoint: true` 在每轮后暂停，允许用户读分数、给自定义指令或提前停止

## 核心 Workflows

### Workflow 1: Idea Discovery (`/idea-discovery`)

> *"有研究方向，没有具体想法"*

流程：`/research-lit`（文献综述）→ `/idea-creator`（头脑风暴 8-12 idea）→ `/novelty-check`（新颖性验证）→ pilot 实验（GPU 30min-2hr）→ 排名 → `/research-refine`（方法打磨）→ `/experiment-plan`（实验路线图）

输出：`IDEA_REPORT.md` + `FINAL_PROPOSAL.md` + `EXPERIMENT_PLAN.md`

### Workflow 1.5: Experiment Bridge (`/experiment-bridge`)

> *"有计划，需要实现和部署"*

流程：解析 `EXPERIMENT_PLAN.md` → 实现脚本 → GPT 代码审查（默认开启）→ 最小实验健全性检查 → 部署到 GPU → 收集初始结果

路由逻辑：≤5 任务 → `/run-experiment`；≥10 任务或有阶段依赖 → `/experiment-queue`（含 OOM 重试、wave 过渡保护）

### Workflow 2: Auto Review Loop (`/auto-review-loop`)

> *"有结果，需要迭代改进"*

4 轮自主评审循环：GPT reviewer 打分并给出具体修改建议 → Claude executor 实现修改（可能包括自动跑补充实验）→ 下一轮

真实案例：5.0/10 → 6.5 → 6.8 → 7.0 → **7.5/10**（自主跑 20+ GPU 实验，重构论文叙事框架）

### Workflow 3: Paper Writing (`/paper-writing`)

> *"有结果，需要写论文"*

分阶段：`/paper-plan`（结构规划 + Gap Report）→ `/paper-figure`（图表生成）→ `/paper-write`（LaTeX 撰写）→ `/paper-compile`（编译检查）→ `/auto-paper-improvement-loop`（自动改进循环）→ Phase 5.6 Kill Argument（对抗性攻防）→ 审计级联

`— style-ref:` 选项：参考已有论文的结构风格（章节顺序、定理/图密度）而不复制内容。

### Workflow 4: Rebuttal (`/rebuttal`)

> *"收到评审意见，需要撰写 rebuttal"*

7 阶段流水线，3 道安全门：
1. 🔒 **No fabrication**：每个声明映射到论文/评审/用户确认结果
2. 🔒 **No overpromise**：每个承诺须用户确认
3. 🔒 **Full coverage**：每条 reviewer 意见均被追踪

输出：`PASTE_READY.txt`（精确字数，直接粘贴）+ `REBUTTAL_DRAFT_rich.md`（供手动编辑）

### Effort 轴

| Effort | 乘数 | 适用场景 |
|---|---|---|
| `lite` | 0.4× | 快速探索，节省 token |
| `balanced` | 1× | 默认，常规研究 |
| `max` | 2.5× | 提交前强化 |
| `beast` | 5–8× | 顶会冲刺，所有旋钮拉满 |

## Evidence-to-Claim 审计级联

ARIS v0.4.1+ 引入强制审计机制（`effort: max/beast` 时默认开启 `assurance: submission`）：

```
experiment-audit (代码层)
    ↓ advisory verdict
result-to-claim (科学层)
    ↓ reads audit if present
paper-claim-audit (报告层，零上下文)
    ↓ compares paper numbers vs raw result files
citation-audit (引用层，独立 reviewer)
    ↓ KEEP/FIX/REPLACE/REMOVE per entry
Final Report (SHA256 input hashing, non-zero exit blocks)
```

每层产出 6-state JSON verdict（`assurance-contract.md` 定义）。`verify_paper_audits.sh` 作为外部 source-of-truth 验证器。

## 关键设计原则（5 条）

1. **异构模型（Heterogeneous Models）**：executor 与 reviewer 来自不同模型家族，最小化共享盲区
2. **模块化 Skills（Modular Skills）**：每个 skill 独立、自包含，互不耦合
3. **可组合性（Composability）**：skills 链接成 workflows，workflows 链接成完整流水线
4. **可移植性（Portability）**：Markdown-only，无框架依赖；在 6+ executor 平台上验证可用
5. **持久记忆（Persistent Memory）**：Research Wiki 跨 session 积累论文/想法/失败经验；meta-optimize 分析使用日志自动改进 harness 本身

## 个人观察与启发

**ARIS 做得好的地方：**
- **跨模型审查框架**的设计哲学非常清晰——self-play 盲区问题是真实存在的，用不同家族模型作 reviewer 是有说服力的解决方案
- **Evidence-to-Claim 级联**解决了 AI 辅助写作中最危险的问题：幻觉引用和数据与声明不符
- **Skills-as-Prompts** 极简主义有真正的优点：无框架依赖意味着任何能读 Markdown 的 agent 都能运行，这是真正的可移植性
- **Persistent Research Wiki** + **Meta-Optimize** 组合形成了一个"自我改进研究助手"的雏形，方向前瞻

**局限与疑问：**
- **AI-review scores ≠ acceptance**：ARIS 显式针对 AI reviewer 优化，这必然导致 AI review 分数虚高（报告自称知晓，但 community showcase 中的 8/10 仍容易被误读为泛化性能）
- **Reviewer 独立性的深层问题**：即使跨模型，如果两个模型都在 RLHF 阶段使用了类似数据，共享盲区仍然存在；"对抗 bandit" 类比假设 reviewer 真正对抗，实际上 GPT 和 Claude 都倾向于礼貌性批评
- **本知识库的关系**：本 wiki 本身就是 ARIS 哲学的实践（Karpathy LLM Wiki 方法论 + Claude Code 执行）。这是一个有趣的自指关系——这个知识库的 CLAUDE.md 配置体现了 Harness Engineering 的精神，而 ARIS 是这一精神在研究流程上的系统化
