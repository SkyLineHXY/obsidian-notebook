## 一句话摘要

π₀.₅ 在 π₀ 基础上，用**异构数据 co-training** + **单模型分层推理**（先离散自回归预测语义子任务 $\hat\ell$，再基于 $\hat\ell$ 用 flow matching 生成连续动作块），首次让端到端 VLA 在**完全没见过的真实家庭**里完成 10–15 分钟的长时程清洁任务。

---

## 核心背景与动机

### 问题：Open-World Generalization

VLA 已能端到端控制机器人，但几乎总是在**与训练数据高度相似**的环境里评测。对"打扫一个全新厨房"这类长时程任务，靠暴力扩充机器人数据来覆盖所有场景是不可行的。真正的泛化需要**在多个抽象层次上迁移知识**：

- 底层技能（抓盘子/开抽屉）——只要数据里场景/物体够多就能泛化；
- 技能重组——需要把已有技能用在新序列里；
- 语义理解——需要先验知识（哪个抽屉放餐具、台面上哪个是沥水架）。

### 关键洞察

单靠规模不够，需要设计能吸收**异构知识源**的训练配方。VLA 的序列建模框架天然能把机器人动作、网页图文、检测框、语义子任务统一成 token 序列，因此可以在**同一个模型**里 co-train 所有这些来源。关键统计：第一阶段训练样本中 **97.6% 不来自移动机械臂做家务**，而来自其它机器人 / 网页数据 —— 泛化正是靠这种跨源迁移涌现的。

## 方法：π₀.₅ 模型与训练配方

### 1. 分层分布分解（子任务推理的数学基础）

模型联合建模动作块 $\mathbf{a}_{t:t+H}$ 与文本输出 $\hat\ell$，分解为两级：

$$
\pi_\theta(\mathbf{a}_{t:t+H}, \hat\ell \mid \mathbf{o}_t, \ell) = \underbrace{\pi_\theta(\mathbf{a}_{t:t+H} \mid \mathbf{o}_t, \hat\ell)}_{\text{低层：动作}} \cdot \underbrace{\pi_\theta(\hat\ell \mid \mathbf{o}_t, \ell)}_{\text{高层：子任务}}
$$

其中：
- $\mathbf{o}_t = [\mathbf{I}_t^1,\dots,\mathbf{I}_t^n, \mathbf{q}_t]$：多相机图像 + 本体状态（关节、夹爪、躯干升降、底盘速度）；
- $\ell$：总任务 prompt（如 "put away the dishes"）；
- $\hat\ell$：模型输出的**语义子任务**（如 "pick up the plate"）或网页 VQA 的答案；
- **关键点**：动作分布**不依赖原始任务 $\ell$，只依赖子任务 $\hat\ell$**。高层负责"看着场景决定下一步做什么"，低层只负责"执行这个子任务"。这与 chain-of-thought / test-time compute 同构，但高层推理频率低于低层动作推理。

### 2. 离散 + 连续动作的混合表示

同一动作用两种方式同时训练，用注意力掩码隔离，各取所长：

- **离散（FAST tokens）**：用 FAST tokenizer 把动作块压缩成离散 token，自回归预测。训练快、语言跟随能力强，但推理需昂贵的自回归解码。
- **连续（Flow Matching）**：给定 $\mathbf{a}_{t:t+H}^{\tau,\omega} = \tau\,\mathbf{a}_{t:t+H} + (1-\tau)\,\omega,\ \omega\sim\mathcal N(0,\mathbf I)$，模型预测向量场 $\omega - \mathbf{a}_{t:t+H}$。推理时只需 10 步去噪即可产生细粒度连续动作，实时性好。

联合损失（Eq. 1）：

$$
\mathbb{E}_{\mathcal D,\tau,\omega}\Big[\; H\big(x_{1:M},\, f_\theta^\ell(\mathbf o_t,\ell)\big) \;+\; \alpha\,\big\|\,\omega - \mathbf{a}_{t:t+H} - f_\theta^a(\mathbf{a}_{t:t+H}^{\tau,\omega},\mathbf o_t,\ell)\,\big\|^2 \;\Big]
$$

第一项是文本 token（含 FAST 动作 token、子任务）的交叉熵，第二项是动作专家的 flow-matching MSE，$\alpha$ 为权衡系数。$\alpha=0$ 时就是纯 VLM 离散训练。

### 3. 两阶段训练

| 阶段                | 步数   | 表示                                                    | 数据                                       | 说明                      |
| ----------------- | ---- | ----------------------------------------------------- | ---------------------------------------- | ----------------------- |
| **Pre-training**  | 280k | 全离散 FAST token（$\alpha=0$）                            | MM + ME + CE + HL + WD                   | 当作标准自回归 VLM 训练，稳定且语言跟随强 |
| **Post-training** | +80k | 加入随机初始化的 **action expert**（flow matching），$\alpha=10$ | MM + ME（成功且短的 episode）+ WD + HL + **VI** | 专精移动操作 + 获得实时推理能力       |

### 4. 数据源（co-training 配方）

- **MM**：约 400h 移动机械臂家务数据，约 100 个真实家庭；
- **ME**：非移动（固定）单/双臂在多样家庭环境采集，更易搬运→环境更多样；
- **CE**：实验室跨机身数据（含 Open X-Embodiment），任务从"装盘子入箱"到"磨咖啡豆"；
- **HL**：把"打扫卧室"拆成"整理毯子/捡枕头"等子任务标注，还标注 bounding box（先预测框再预测子任务）；
- **WD**：网页多模态（captioning、VQA、物体定位）；
- **VI**（仅 post-training）：专家用"语言遥操作"实时给已训练策略下达好的子任务序列，即"高层策略的示范"。

### 5. 架构细节（Appendix E）

- **Backbone**：PaliGemma 2B VLM（width=2048, depth=18, mlp=16384, heads=18, kv_heads=1, head_dim=256）；
- **Action expert**：约 300M（width=1024, mlp=4096），动作时域 50（$H=49$）；
- **时间条件**：与 π₀ 不同，π₀.₅ 用单独 MLP 编码 $\tau$，再用 **adaptive RMSNorm** 把时间信息注入动作专家每一层（$\mathrm{swish}(W_2\cdot\mathrm{swish}(W_1\cdot\phi(\tau)))$，$\phi$ 为正弦位置编码）；
- **注意力**：前缀（图像/prompt/连续动作）用双向注意力；信息**单向**从 VLM 流向 action expert，且 action expert **不注意 FAST token**（避免两种动作表示互相泄漏）；本体状态离散化后作为文本 token 输入；
- **控制**：50Hz 直接输出手臂/夹爪/躯干/底盘目标，PD 控制器跟踪，无轨迹规划/碰撞检测，全端到端，18–19 DoF。

## 子任务推理机制（结合代码仓库 `pi05_full`）

用户重点关注"π₀.₅ 是怎么推理 subtask 的"。论文给出原理，代码 `modeling_pi05.py` 给出精确实现。推理链路：`select_action` → `predict_action_chunk` → `generate_subtask_tokens` → `sample_actions`。

### 高层：`generate_subtask_tokens`（自回归解码子任务文本）

1. **Prefill**：`embed_prefix` 把 `[图像, 语言prompt | BOS]` 编码，其中 **BOS 放在 subtask 段**（而非语言段）以匹配训练时的注意力结构，一次前向填充 KV cache（`use_cache=True`）。
2. **逐 token 解码**（最多 `max_decoding_steps=24` 步）：用 `lm_head` 取最后一个位置 logits，贪心 `argmax`（`temperature=0`）取下一 token，追加进 KV cache 继续。
	1. **特殊 token 屏蔽**：把 `<loc0000>` 及之后所有 ID 置为 $-\infty$（`last_logits[:, -1, loc0_id:] = -inf`），防止子任务文本解码时误吐出定位/FAST 动作 token。
3. **停止**：遇到 EOS 即标记该序列 finished，后续填 pad(0)；全 batch finished 则提前退出。
4. **返回**：在返回前**补上 BOS**（`[BOS, tok1, tok2, ...]`），修复训练/推理的 1 位 RoPE 偏移（见下方 KNOWN_BUGS）。

> 对应论文的"高层先预测语义子任务 $\hat\ell$"。子任务是**纯文本**（如 "pick up the plate"），由同一个 VLM backbone 生成，不经过 action expert。

### 频率解耦：子任务缓存（`predict_action_chunk`）

代码用 `subtask_regeneration_interval=2`（秒）实现论文所说"高层推理频率低于低层"：只有当无缓存 / 距上次生成超过 2s / interval≤0 时才重新 `generate_subtask_tokens`，否则复用 `_cached_subtask_tokens`。这样 50Hz 的动作推理里，子任务大约每 2 秒才更新一次。

### 低层：`sample_actions`（子任务条件下的 flow matching）

1. `embed_prefix` 编码 `[图像, 高层任务, 子任务]`（**推理时不含 FAST token**），前向填充 KV cache。
2. 从高斯噪声 $x_t$（shape `[B, chunk_size=50, max_action_dim=32]`）出发，做 `num_inference_steps=10` 步欧拉积分：
   - `dt = -1/num_steps`，`time` 从 1.0 递减到 0；
   - 每步 `denoise_step` 用 action expert 预测向量场 $v_t$，更新 $x_t \leftarrow x_t + dt \cdot v_t$；
   - `denoise_step` 里 action expert 注意前缀 KV（含子任务）但每步后 `crop` 回前缀长度以稳定 cache。
3. 输出去 padding 到真实动作维度，`select_action` 用长度 50 的动作队列逐步出队执行。

> 对应论文"conditioned on subtask, predict low-level actions via action expert，10 denoising steps"。

### 已知 Bug（KNOWN_BUGS.md）

训练时子任务段以 `<bos>` 开头，早期推理版本 `generate_subtask_tokens` 返回时**丢了 BOS**，造成 action diffusion model 前缀的 train/inference 分布不一致。当前 commit 已在返回前 `cat([bos_col, tokens[:, :-1]])` 修复。这提示：分层 VLA 里高层文本与低层动作共享注意力前缀，**子任务段的 token 对齐（含特殊 token）会直接影响动作质量**。

## 训练 Pipeline（结合代码仓库）

代码 `PI05Pytorch.forward` 精确对应论文 Eq. (1) 的联合目标，一次前向同时算**三个损失**：

| 损失                | 代码变量              | 计算                                                                                       | 论文对应                 |
| ----------------- | ----------------- | ---------------------------------------------------------------------------------------- | -------------------- |
| Flow matching MSE | `flow_mse_loss`   | $x_t = t\cdot\text{noise} + (1-t)\cdot a$，目标 $u_t=\text{noise}-a$，`F.mse_loss(u_t, v_t)` | Eq.(1) 第二项           |
| FAST 动作 CE        | `action_ce_loss`  | 对 FAST token 做 shift-by-one 自回归交叉熵                                                       | Eq.(1) 第一项（动作 token） |
| 子任务 CE            | `subtask_ce_loss` | 对子任务 token 做 shift-by-one 交叉熵                                                            | Eq.(1) 第一项（HL 文本）    |

总损失 `loss = w_flow·flow + w_action_ce·action_ce + w_subtask_ce·subtask_ce`，三个权重默认均为 1.0。

### Knowledge Insulation（`knowledge_insulation=True`，默认开）

`compute_layer_complete_knowledge_insulation` 实现"知识绝缘"：
- 前向：action expert 的 query **可以**注意 VLM 的 K/V（跨注意力照常）；
- 反向：把 action expert 看到的 VLM K/V **detach**，使 flow-matching/动作损失的梯度**不回流进 VLM backbone 的 K/V 投影**；
- VLM 自注意力、action expert 自注意力梯度不变。

这在工程上落地了论文"离散预训练稳住 VLM 语言能力，再挂 flow action expert"的思想：动作专家的连续回归损失不会破坏 VLM 已学到的语义/语言跟随能力。

### 自定义注意力掩码（`_create_custom_attention_mask`）

严格复刻论文 Figure 18 的信息流：
- **图像 + 语言**：彼此双向，不注意 subtask / FAST；
- **Subtask**：注意 图像+语言，自身因果，不注意 FAST；
- **FAST**：注意 图像+语言+subtask，自身因果；
- **Action expert（suffix）**：注意前缀但**排除 FAST token**（`prefix_without_fast_len = image_len + language_len + subtask_len`），即两种动作表示互不泄漏。

### 数据处理（`processor_pi05.py`）

- Prompt 格式：`Task: {task}, State: {discretized_state};\n`；子任务格式：`Subtask: {cleaned};\n`；
- 本体状态先归一化到 $[-1,1]$，再 `np.digitize` 离散成 256 bin 作为文本 token（对应论文"proprioceptive state discretized and input as text tokens"）；
- 支持 `advantage` 条件（`Advantage: positive/negative`）——这是 π₀.₆/RECAP 系 RL 微调的接口，说明该仓库把 π₀.₅ 作为 RL 后训练底座。

### 关键超参（`configuration_pi05.py`）

- `chunk_size=50`, `n_action_steps=50`, `num_inference_steps=10`, `max_action_dim=32`；
- `max_decoding_steps=24`（子任务最大长度）, `subtask_regeneration_interval=2s`；
- 优化器 AdamW `lr=2.5e-5`, betas=(0.9,0.95), wd=0.01, grad_clip=1.0；
- 调度 CosineDecayWithWarmup：warmup 1k，decay 30k，末端 lr=2.5e-6；
- backbone `gemma_2b` + action expert `gemma_300m`；可选 `gradient_checkpointing` / `torch.compile` / RTC（实时分块）。

> 注：论文描述的是"离散预训练 280k → flow 后训练 80k"两阶段配方；代码仓库提供的是**统一联合目标**的模型实现（Eq.1 全项 + Knowledge Insulation），两阶段是训练脚本层面的数据/α 调度，模型 `forward` 本身已支持三损失同时优化。

## 实验结果

- **真实家庭泛化**：在 3 个训练中未见的真实家庭里完成厨房/卧室清洁，多阶段任务持续 2–5 分钟（整体清洁可达 10–15 分钟），高层自主决定子任务序列。
- **环境数量缩放**：移动操作环境从 3→12→22→53→82→104，泛化性能单调提升；104 环境的最终模型 ≈ 直接在测试家庭上训练的对照模型（绿线），即**co-training 弥合了泛化鸿沟**。
- **消融（哪个数据源重要）**：去掉 ME 或 CE（跨机身数据）显著掉点，两个都去掉更差；去掉 WD（网页数据）对整体任务不显著，但对 **OOD 物体语言跟随**和**高层子任务推理**影响很大。
- **对比 π₀**：π₀.₅ 显著优于 π₀ 及增强版 π₀-FAST+Flow；即便 π₀ 训到 300k 步仍不及，印证 FAST 离散训练比纯 diffusion 更省算力（Pertsch et al.）。
- **高层推理的重要性**：完整 π₀.₅（同模型高层+低层）最好，**甚至超过人类 oracle 高层**；`implicit HL`（训练含子任务数据但推理不显式高层）次之；`no HL`、`no VI`、`no WD` 均显著变差；zero-shot **GPT-4 当高层策略最差**——说明高层必须用机器人数据适配，不能直接套通用 LLM。VI 仅占高层移动操作样本约 11%，但去掉它明显掉点。

## 局限性与未来工作

- 仍会犯错：陌生抽屉把手、物理上难开的柜子、部分可观测（机械臂遮挡待擦的污渍）、高层易分心（反复开关抽屉）。
- prompt 相对简单，复杂偏好/指令受训练标注多样性限制。
- 上下文/记忆有限，跨房间导航、记住物体位置等强部分可观测任务受限。
- 未来：更好的 co-training/迁移、更大数据、更丰富的人类语言监督模态、更长上下文与记忆。

## 新概念追踪

**首次出现，追踪中**:
- **Knowledge Insulation（知识绝缘）**：反向传播时 detach VLM K/V，阻止动作损失梯度污染 VLM backbone；本仓库 `pi05_full` 默认开启；仅本来源，待第二独立来源升级为 concept 页。
- **Subtask Regeneration Interval（子任务频率解耦）**：高层子任务按时间间隔（默认 2s）缓存重生成，低层动作 50Hz；工程化了"高层低频、低层高频"的分层推理；仅本来源。
- **混合离散+连续动作训练（FAST + Flow Matching, 注意力隔离）**：跨 π₀.₅ / π₀.₇ 出现，接近 ≥2 来源阈值，可考虑升级。
